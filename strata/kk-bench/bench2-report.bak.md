# RTX 5060 Ti 16GB で Qwen3.8-Flash-Next を Strata で動かした速度測定

ローカルLLMエンジン **Strata** で、Qwen3.8-Flash-Next の通常版と無検閲版を同じ条件で動かし、生成速度・読み込み速度・応答開始までの時間を測りました。

## 結論

- 生成速度は **約40〜50 tok/s**。通常版が全課題で3〜8%速い
- 長文の読み込み（prefill）は **約1,600〜1,700 tok/s**。1.6万トークンなら約9〜10秒で読み終わる
- 短い質問なら約1秒で回答が出始める
- 3回測った結果のばらつきは小さく、数字は安定している

## 測定環境

| 項目 | 内容 |
|---|---|
| GPU | NVIDIA GeForce RTX 5060 Ti 16GB（ドライバ 591.86） |
| CPU | Intel Core i7-14700F |
| RAM | DDR5-5600 64GB |
| OS | Windows 11 Home |
| エンジン | Strata v0.1.38（CUDA 13.0） |
| モデルA | qwen3.8-flash-next-iq3_xxs（通常版） |
| モデルB | orcarouter-qwen3.8-flash-next-uncensored-iq3_xxs（無検閲版） |
| 測定日 | 2026年10月11日 |

両モデルとも量子化は IQ3_XXS です。モデルを読み込んだ時点で、VRAM は約15.7GB / 16GB 使われていました。

## 測定方法

自作スクリプト（`bench2.py`）から、Strata の OpenAI 互換API（`/v1/chat/completions`）にストリーミングでリクエストを送りました。

- 5種類の課題を **各3回** 実行し、中央値を採用
- 最初にウォームアップを1回実行（記録しない）
- 毎回プロンプトの先頭にランダムなIDを付け、前回の読み込み結果の再利用（プレフィックスキャッシュ）が効かないようにした
- 測定中は他のアプリをすべて終了した

| 課題 | 内容 | 入力トークン | 出力上限 | reasoning_effort |
|---|---|---|---|---|
| short_ja | 短い日本語の質問 | 約80 | 1,000 | low |
| summary_3k | 長めの文章を3行に要約 | 3,547 | 1,000 | low |
| long_16k | 長文から工程名を列挙 | 15,745 | 400 | low |
| code_medium | C言語でリングバッファを実装 | 61 | 6,000 | medium |
| refusal_check | 錠の構造の技術解説 | 46 | 2,000 | medium |

計測した指標は次の3つです。

- **生成速度**：出力トークン数 ÷（全体時間 − 応答開始までの時間）
- **読み込み速度**：入力トークン数 ÷ 応答開始までの時間
- **TTFT**：リクエストを送ってから最初のトークンが届くまでの時間

## 結果

### 生成速度（tok/s、中央値。かっこ内は3回の最小〜最大）

| 課題 | 通常版 | 無検閲版 | 差 |
|---|---|---|---|
| short_ja | **42.8**（41.5〜44.5） | 39.5（38.7〜42.2） | +8% |
| summary_3k | **46.6**（46.4〜48.1） | 43.2（41.0〜43.8） | +8% |
| long_16k | **49.9**（49.9〜50.1） | 48.9（45.3〜51.1） | +2% |
| code_medium | **50.7**（50.4〜52.9） | 46.8（46.4〜46.8） | +8% |
| refusal_check | **46.4**（44.4〜47.5） | 46.1（46.1〜46.3） | +1% |

### 読み込み速度とTTFT（中央値）

| 課題 | 入力トークン | 読み込み速度 通常版 / 無検閲版 | TTFT 通常版 / 無検閲版 |
|---|---|---|---|
| short_ja | 約80 | 60 / 54 tok/s | 1.3 / 1.5 秒 |
| summary_3k | 3,547 | 1,007 / 855 tok/s | 3.5 / 4.2 秒 |
| long_16k | 15,745 | 1,589 / 1,710 tok/s | 9.9 / 9.2 秒 |
| code_medium | 61 | 54 / 49 tok/s | 1.1 / 1.2 秒 |
| refusal_check | 46 | 50 / 45 tok/s | 1.0 / 1.0 秒 |

短い入力では読み込み速度の数字が小さく出ますが、これは計算式の都合です。入力が数十トークンしかないため、通信やリクエスト処理にかかる約1秒の固定時間がそのまま分母に入っています。入力が長いほど本来の読み込み速度に近づき、1.6万トークンでは約1,600〜1,700 tok/s になりました。

### 1回あたりの所要時間（中央値）

| 課題 | 通常版 | 無検閲版 |
|---|---|---|
| short_ja | 6.4 秒 | 7.7 秒 |
| summary_3k | 7.1 秒 | 9.5 秒 |
| long_16k | 17.9 秒 | 17.0 秒 |
| code_medium | 64.1 秒（約3,200トークン出力） | 54.2 秒（約2,500トークン出力） |
| refusal_check | 29.0 秒 | 28.3 秒 |

所要時間には出力した量の差も含まれます。たとえば code_medium では、無検閲版のほうが出力が短かったため早く終わっています。速度を比べるときは、上の生成速度の表を見てください。

## まとめ

16GB の GPU でも、IQ3_XXS まで量子化すれば Qwen3.8-Flash-Next クラスを **約40〜50 tok/s** で動かせました。読む速度より速く文字が出てくるので、チャット用途なら待ち時間はほとんど気になりません。長文の要約でも、1.6万トークンを約10秒で読み終えます。

速度だけで比べると、通常版が全課題で無検閲版を上回りました。ただ差は1〜8%なので、体感できる差はほぼないと思います。

## 補足

- 結果は Strata v0.1.38 のものです。このあとエンジンを更新すると数字が変わる可能性があります
- long_16k は出力上限を400トークンにしていたため、出力量が少なめです。生成速度の測定には影響ありません
- 測定データは `v2-strata-20261011-124138.json` と `v2-orca-20261011-124838.json` に残してあります
